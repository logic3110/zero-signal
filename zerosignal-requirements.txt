================================================================================
1. PRODUCT OVERVIEW
================================================================================
ZeroSignal is an Android app that gives expert-grade, cited, step-by-step
guidance for emergency medicine, wilderness/disaster survival and roadside
vehicle repair with NO internet connection.

It combines:
  a) A curated, source-cited offline library (usable without AI).
  b) Hybrid offline search (SQLite FTS5 keyword + vector semantic search).
  c) An on-device small language model (2B-4B parameters) that ONLY rewrites
     retrieved library passages into numbered, cited action steps (RAG).
  d) Instant, human-reviewed emergency protocol cards for life-threatening
     situations that never depend on the LLM.
  e) Non-AI field tools: SOS, compass, flashlight, trip card, supplies,
     OBD-II code lookup.

Core principle: the app must be fully useful without the AI model, and the
AI must never answer from its own memory - only from the vetted library, with
citations.

Tagline (working): "No signal. Still an answer."

================================================================================
2. GOALS AND NON-GOALS
================================================================================
GOALS
  G1  100% of core functionality works in airplane mode after install.
  G2  Run on an average Android phone (6 GB RAM, Snapdragon 7-series /
      Dimensity 7000-class, Android 10+).
  G3  Every AI answer is grounded in and cites library sources.
  G4  Life-threatening situations get a correct protocol on screen in < 1 s.
  G5  Answers in three expert domains: emergency medicine, survival,
      vehicle repair.
  G6  No accounts, no analytics, no data leaves the device.
  G7  Multilingual (English first, then Hindi and other regional languages).

NON-GOALS
  NG1 Not a medical device, not a diagnosis tool, not a replacement for a
      clinician, emergency services or a certified mechanic.
  NG2 Not live GPS turn-by-turn navigation or live maps.
  NG3 Not a general-purpose chatbot; out-of-domain questions are declined.
  NG4 No cloud inference, no cloud sync of personal data (v1).
  NG5 No iOS in v1 (architecture should not block a later port).

3. USER PERSONAS
================================================================================
P1  "Trekker Tara" - hiker/trekker in Himalaya/Western Ghats. Often no signal
    for days. Needs first aid, navigation fallback, weather/altitude advice.
P2  "Driver Dev" - long-distance driver/biker on highways and ghats. Needs
    roadside fixes, warning-light meanings, accident first aid.
P3  "Household Heena" - parent preparing for floods, cyclones, heatwaves,
    power cuts. Needs plans, supply tracking, child/elderly first aid.
P4  "Volunteer Vikram" - community first responder / NGO / ASHA worker in
    low-connectivity areas. Needs fast triage protocols, dosage-safe info,
    regional language.
P5  "Curator Chris" - internal content curator / developer who builds and
    reviews knowledge packs.
P6  "Reviewer Dr. Rao / Mechanic Mani" - domain expert who signs off content
    and evaluates AI answers.

E1  ONBOARDING AND INSTALLATION
--------------------------------------------------------------------------------
US-1.1 [MVP]
  As a new user, I want to install the app and immediately use the library
  and tools without creating an account, so that I can be ready before I lose
  signal.
  AC:
   - No login/sign-up screen exists.
   - Library, search, protocol cards and field tools work on first launch.
   - Base APK/AAB (without LLM) <= 150 MB including the core library.

US-1.2 [MVP]
  As a new user, I want a short onboarding (max 4 screens) that explains what
  works offline, what the AI can and cannot do, and the medical disclaimer.
  AC:
   - Disclaimer must be acknowledged once before first use of Ask.
   - Onboarding can be skipped and revisited from Settings.

US-1.3 [MVP]
  As a user, I want the app to detect my phone's RAM/SoC and recommend the
  right AI pack (Compact or Recommended), so I don't download something that
  won't run.
  AC:
   - Device with < 6 GB RAM: Ask shown as "not supported" OR Compact only
     with warning.
   - 6-7 GB: Compact recommended.
   - >= 8 GB: Recommended pack offered as default.

US-1.4 [MVP]
  As a user, I want to download the AI model and knowledge packs only over
  Wi-Fi (with an override), so I don't burn mobile data.
  AC:
   - Download is resumable after interruption.
   - SHA-256 checksum verified after download; corrupt files are re-fetched.
   - Progress, size and remaining time are shown.

US-1.5 [P1]
  As a user, I want a "Ready check" screen that confirms everything needed is
  downloaded and working offline (library, model, tools, emergency contacts).
  AC:
   - Runs a local test query through the model and reports pass/fail.
   - Shows storage used per component.

US-1.6 [P1]
  As a user, I want a guided "airplane mode test" so I can verify offline
  behaviour before a trip.

E2  OFFLINE KNOWLEDGE LIBRARY
--------------------------------------------------------------------------------
US-2.1 [MVP]
  As a user, I want to browse guides by domain (Medical, Survival, Vehicle)
  and category (e.g. Bleeding, Burns, Water, Fire, Shelter, Engine, Tyres),
  so I can find information without typing.
  AC:
   - Three top-level domains, each with categories and guides.
   - Guide list loads in < 300 ms offline.

US-2.2 [MVP]
  As a user, I want each guide to show clear numbered steps, warnings,
  "when to seek help" and the original source with citation.
  AC:
   - Every guide has: title, summary, steps, warnings, red flags, sources,
     last-reviewed date, reviewer role.
   - Source list shows publisher, document title, section, licence.

US-2.3 [MVP]
  As a user, I want to bookmark guides and see recently opened guides.
  AC:
   - Bookmarks persist across app restarts; stored locally only.

US-2.4 [MVP]
  As a user, I want guides to render well in sunlight and at night.
  AC:
   - Light ("Sunlight") and dark red-tinted ("Night/Field") themes.
   - Minimum body text 16sp, scalable with system font size.

US-2.5 [P1]
  As a user, I want diagrams/illustrations in guides (e.g. recovery position,
  tourniquet placement, jack points, knots) that work offline.
  AC:
   - Images bundled as compressed WebP/SVG; total illustration budget
     defined per pack.

US-2.6 [P1]
  As a user, I want to jump from an AI answer citation straight to the exact
  section of the source guide, highlighted.

US-2.7 [P2]
  As a user, I want to print/export a guide to PDF for a physical kit.

E3  SEARCH (KEYWORD + SEMANTIC)
--------------------------------------------------------------------------------
US-3.1 [MVP]
  As a user, I want to type a query and get relevant guide sections instantly
  even when the AI model is not installed.
  AC:
   - Uses SQLite FTS5 (BM25) keyword search.
   - Results in < 200 ms on a mid-range phone for the full library.
   - Typo tolerance (prefix + trigram or synonym table).

US-3.2 [MVP]
  As a user, I want search to understand meaning, not only exact words
  (e.g. "car won't start clicking noise" -> "weak battery / starter").
  AC:
   - Query embedded on-device (EmbeddingGemma-300M or multilingual-e5-small,
     int8), vector search via sqlite-vec (or ObjectBox HNSW).
   - Hybrid ranking: BM25 + vector merged with Reciprocal Rank Fusion.
   - Hybrid search latency < 500 ms p95 on target device.

US-3.3 [MVP]
  As a user, I want to filter results by domain.

US-3.4 [P1]
  As a user, I want a synonym/lay-term layer so common words map to
  technical ones (e.g. "fits" -> seizure, "puncture" -> flat tyre,
  "check engine light" -> MIL/OBD).
  AC:
   - Curated synonym table per language, versioned with the pack.

US-3.5 [P1]
  As a user, I want recent searches saved locally, with a one-tap clear.

E4  ASK - OFFLINE RAG ANSWERS
--------------------------------------------------------------------------------
US-4.1 [MVP]
  As a user, I want to ask a question in natural language and get numbered
  action steps generated on-device from the library.
  AC:
   - Works in airplane mode.
   - Answer format: (1) one-line situation summary, (2) numbered steps,
     (3) warnings / do-NOTs, (4) when to get professional help,
     (5) sources.
   - Time to first token < 4 s (Compact pack, 6 GB phone), streaming output.
   - Decode speed >= 8 tokens/s on target device.

US-4.2 [MVP]
  As a user, I want every step in the answer to cite its source passage, so
  I can trust and verify it.
  AC:
   - Each step ends with [n] referencing a retrieved chunk.
   - Post-generation validator removes/flags steps whose citation id was
     not in the retrieved context.
   - Tapping [n] opens the source guide section (US-2.6).

US-4.3 [MVP]
  As a user, I want the app to say "This isn't covered in the library"
  instead of guessing when it has no good source.
  AC:
   - If top retrieval score < configured threshold, the LLM is NOT called;
     show "Not in library" + the 3 closest guides.
   - System prompt forbids answering beyond the provided context.

US-4.4 [MVP]
  As a user, I want out-of-scope questions (e.g. coding, politics) politely
  declined.
  AC:
   - Domain router classifies query as medical / survival / vehicle / other.
   - "other" -> polite decline, no generation.

US-4.5 [MVP]
  As a user, I want to stop generation at any time and still see the sources.

US-4.6 [MVP]
  As a user, I want the phone not to overheat or die during long use.
  AC:
   - Max output tokens capped (default 350).
   - Model unloaded after N minutes idle; thermal-throttle detection reduces
     threads.
   - Battery-saver mode: disables Ask, keeps library/search.

US-4.7 [P1]
  As a user, I want to ask a follow-up question in the same context
  ("what if they are a child?").
  AC:
   - Keeps last 1-2 turns + re-retrieves using combined query.
   - Context window budget enforced (e.g. 2,048-4,096 tokens).

US-4.8 [P1]
  As a user, I want to save or share an answer as text (share works later
  when signal returns).

US-4.9 [P1]
  As a user, I want a "More detail" / "Simpler" toggle on an answer.

US-4.10 [P2]
  As a user, I want to attach a photo (e.g. dashboard warning light, wound,
  plant) and get relevant library guidance.
  AC:
   - Uses multimodal model (Gemma 4 E2B/E4B or Qwen3.5 vision) on-device.
   - Image is only used to form a query; answer must still cite library.
   - Clear warning that visual identification may be wrong (esp. plants,
     mushrooms, snakes).

E5  EMERGENCY PROTOCOL CARDS (RED-FLAG FAST PATH)
--------------------------------------------------------------------------------
US-5.1 [MVP]
  As a user in a life-threatening situation, I want the correct emergency
  protocol on screen immediately, without waiting for AI.
  AC:
   - Red-flag detector (keyword list + lightweight classifier, multilingual)
     runs BEFORE retrieval/LLM.
   - Matching card displayed in < 1 s; LLM answer (if any) appears below.
   - Cards are static, human-authored, expert-reviewed JSON - never
     LLM-generated.

US-5.2 [MVP]
  As a user, I want a big "EMERGENCY" button on the home screen that opens
  the protocol card grid.
  AC:
   - Reachable in 1 tap from home and from a lock-screen widget / quick
     settings tile [P1].
   - Minimum MVP cards:
     MEDICAL : Not breathing / CPR (adult, child, infant), Choking,
               Severe bleeding / tourniquet, Shock, Anaphylaxis,
               Heart attack signs, Stroke (FAST), Seizure, Burns,
               Head/neck/spine injury, Heatstroke, Hypothermia,
               Drowning, Snakebite, Poisoning, Fractures,
               Diabetic emergency, Asthma attack.
     SURVIVAL: Lost (Stop-Mark-Stay-Signal), Flood, Earthquake, Cyclone,
               Wildfire, Lightning, Landslide, Wild animal encounter.
     VEHICLE : Vehicle fire, Accident scene safety, Brake failure,
               Stuck on railway crossing, Vehicle in water,
               Overheating in traffic/hills, Tyre burst at speed.

US-5.3 [MVP]
  As a user performing CPR, I want a metronome (100-120 bpm) with voice/
  vibration cues and a compression/breath counter.

US-5.4 [MVP]
  As a user, I want each card to show the local emergency number
  (e.g. 112/108 in India) and a one-tap call button when signal exists.
  AC:
   - Country auto-detected from SIM/locale, overridable in Settings.

US-5.5 [P1]
  As a user, I want timers on cards (tourniquet time, seizure duration, time
  since snakebite) that log timestamps for handover to medics.

US-5.6 [P1]
  As a user, I want a handover summary ("patient card") I can show/read to
  paramedics: what happened, times, actions taken.

US-7.2 [MVP]

US-7.3 [MVP]

US-7.6 [P2]

US-7.7 [P2]

--------------------------------------------------------------------------------
US-9.1 [MVP]
  As a driver, I want roadside guidance for: flat/burst tyre change, jump

US-9.2 [MVP]
  As a driver, I want a symptom-based troubleshooter ("won't start",
  "clicking", "smoke", "vibration") that narrows causes step by step.
  AC:
   - Deterministic decision trees (JSON) authored and reviewed; the LLM may

US-9.3 [MVP]
  As a driver, I want a dashboard warning-light reference with icons,
  meaning, severity (stop now / drive carefully / check soon).

US-9.4 [P1]
  As a driver, I want an offline OBD-II code lookup (P0xxx, P2xxx, B, C, U

US-9.5 [P1]
  As a driver, I want to save my vehicle profile (make, model, year, fuel

  AC:
   - Stored locally; used as retrieval filter/prompt variable.

US-9.6 [P2]
  As a driver, I want to connect a Bluetooth ELM327 OBD-II dongle to read

US-9.7 [P2]

  on-device (depends on US-4.10).

E10 FIELD TOOLS (NON-AI, ALWAYS AVAILABLE)
--------------------------------------------------------------------------------
US-10.1 [MVP]  SOS flashlight
  As a user, I want a flashlight with steady, strobe and Morse SOS modes,
  plus full-screen white/red/SOS flash for phones without torch access.

US-10.2 [MVP]  SOS message
  As a user, I want one-tap SMS to my emergency contacts with my GPS
  coordinates, time and a short message, because SMS works on weak signal.
  AC:
   - Uses device GPS (no data needed); includes lat/long in decimal and
     plus-code; queues and retries until sent.
   - User confirms before sending (prevent accidental SMS).

US-10.3 [MVP]  Compass
  As a user, I want a compass with bearing, calibration prompt and a
  "mark bearing / follow bearing" feature.

US-10.4 [MVP]  My location
  As a user, I want to see my current and last-known GPS coordinates,
  altitude and accuracy, readable aloud, without internet.

US-10.5 [MVP]  Emergency contacts & numbers
  As a user, I want local emergency numbers (police/ambulance/fire/disaster/
  women's helpline/roadside) by country bundled offline, plus my own
  emergency contacts.

US-10.6 [P1]  Trip card ("leave a card")
  As a trekker/driver, I want to create a trip card (route, people, vehicle,
  start/return time, turn-back time, gear) and share it before leaving;
  app reminds me at the expected return time.

US-10.7 [P1]  Breadcrumb trail
  As a trekker, I want to record a GPS breadcrumb track offline and follow
  it back ("backtrack") with compass guidance.

US-10.8 [P1]  Medical ID
  As a user, I want a medical ID (blood group, allergies, conditions,
  medications, emergency contact) accessible from the lock screen.

US-10.9 [P1]  Radio reference and MAYDAY script
  As a user, I want radio channel references (marine VHF 16, aviation
  121.5, PMR/FRS, local ham repeaters) and a MAYDAY/PAN-PAN script
  auto-filled with my position.

US-10.10 [P2] Signal mirror / whistle
  As a user, I want a whistle (loud audio SOS pattern) and signal-mirror
  aiming guide.

US-10.11 [P2] Offline map tiles
  As a trekker, I want optional downloadable offline map tiles (OSM/
  MapLibre) for a region to see my position.

E12 MODEL AND PACK MANAGEMENT
--------------------------------------------------------------------------------
US-12.1 [MVP]
  As a user, I want to choose between AI packs:
    - Compact    : ~2B model, Q4, ~1.3-1.6 GB   (6 GB RAM phones)
    - Recommended: ~3-4B model, Q4, ~2-3 GB     (8 GB+ RAM phones)
  AC:
   - Shows size, RAM needed, expected speed, languages.

US-12.2 [MVP]
  As a user, I want to download/update/delete knowledge packs per domain and
  region independently.
  AC:
   - Pack manifest: id, version, language, size, sha256, min_app_version,

   - Incremental (delta) update when possible; otherwise full replace.

US-12.3 [MVP]
  As a user, I want updates to happen only when I choose (never forced
  mid-emergency).

US-12.4 [P1]
  As a user, I want to side-load packs/models from SD card or share them

  AC:
   - Signature (ed25519) verified before install.

US-12.5 [P1]
  As a developer, I want the runtime abstracted so models can be swapped
  (llama.cpp GGUF, LiteRT-LM, MNN) without app rewrites.

E14 SETTINGS, PRIVACY AND ACCESSIBILITY
--------------------------------------------------------------------------------
US-14.1 [MVP]
  As a user, I want zero analytics, zero accounts and zero network calls

  AC:
   - No analytics SDKs. INTERNET permission used only by download manager.

US-14.2 [MVP]

US-14.3 [MVP]
  As a user with low vision, I want large text, high contrast and full

  AC:

US-14.4 [MVP]
  As a user, I want to set my country/region, units (metric/imperial) and
  language.

US-14.5 [P1]
  As a user, I want an optional app lock (PIN/biometric) for personal data,

E15 CONTENT BUILD PIPELINE (DEVELOPER / CURATOR)

7. TECHNICAL ARCHITECTURE AND STACK
================================================================================
7.1 High-level flow

  BUILD TIME (developer laptop / CI, Python)
    sources.yaml -> fetch/parse -> clean -> structure-aware chunk
      -> metadata tag -> (optional) LLM step-rewrite + human review
      -> embed (same model as device) -> write pack.sqlite
         [guides, chunks, FTS5, sqlite-vec vectors, sources, manifest]
      -> sign -> publish to static CDN + catalog.json

  RUN TIME (Android, fully offline)
    user query (text/voice)
      -> language detect -> red-flag detector ---> Protocol Card (instant)
      -> domain router (medical/survival/vehicle/other)
      -> query embed (on-device) + FTS5 BM25
      -> hybrid merge (RRF) + metadata filters (domain, patient type,
         vehicle profile, region)
      -> (optional) lightweight rerank
      -> confidence gate (below threshold -> "Not in library")
      -> prompt builder (system rules + top-k chunks with ids + question)
      -> on-device LLM (streaming)
      -> citation validator -> render answer + source links

7.2 Android app
  - Language/UI  : Kotlin, Jetpack Compose, Material 3
  - Architecture : MVVM + Clean Architecture, Hilt DI, Coroutines/Flow
  - Modules      : :app, :core-ui, :library, :search, :rag, :llm-runtime,
                   :protocols, :tools, :supplies, :packs, :voice, :settings
  - Storage      : SQLite (Room for app data; raw SQLite for pack DBs with
                   FTS5 + sqlite-vec extension) ; alternative: ObjectBox HNSW
  - LLM runtime  : llama.cpp via JNI (GGUF, mmap) - default
                   LiteRT-LM (GPU/NPU, Gemma family) - optional backend
                   MNN - optional backend for Qwen
  - Embeddings   : EmbeddingGemma-300M or multilingual-e5-small, int8,
                   via ONNX Runtime Mobile or LiteRT
  - Voice        : whisper.cpp (STT), Android TextToSpeech (TTS)
  - Downloads    : WorkManager + resumable HTTP range requests
  - Location     : FusedLocationProvider with GPS-only fallback
                   (LocationManager) - no network location required
  - Sensors      : magnetometer + accelerometer (compass), camera torch
  - Billing      : Google Play Billing Library
  - Crypto       : Tink / libsodium (ed25519 signature verify)

7.3 Build pipeline (Python 3.11+)
  - trafilatura, BeautifulSoup4, PyMuPDF, pytesseract, ebooklib,
    python-docx, PyYAML, pydantic
  - sentence-transformers / onnxruntime for embeddings
  - sqlite3 + sqlite-vec, FTS5
  - Optional: large LLM (local or API) for build-time step rewriting only
  - CLI: `zs-build`, `zs-eval`, `zs-sign`, `zs-publish`
  - (Reusable pieces from ZeroSignal-web: scraper.py, chunker.py,
    config/YAML pack format, deterministic document ids)

7.4 Backend (minimal, optional)
  - No inference server. Static hosting only:
    catalog.json + signed pack/model files on CDN (R2/S3/GitHub Releases).
  - Optional tiny FastAPI for catalog if dynamic features needed later.

7.5 Prompting rules (system prompt essentials)
  - Answer ONLY from the numbered context passages.
  - If the answer is not in the context, say it is not in the library.
  - Output: summary line, numbered steps each ending with [id], warnings,
    when to get help.
  - Never invent medication doses; never contradict a protocol card.
  - Keep language simple; respond in the user's language.
  - Max ~350 tokens.

14. GLOSSARY
================================================================================
RAG            Retrieval-Augmented Generation: retrieve relevant passages,
               then have the LLM answer only from them.
FTS5 / BM25    SQLite full-text search and its keyword ranking function.
sqlite-vec     SQLite extension for vector similarity search.
RRF            Reciprocal Rank Fusion - merges keyword and vector rankings.
GGUF           Model file format used by llama.cpp.
Q4_K_M         A 4-bit quantization level balancing size and quality.
mmap           Memory-mapped file loading; lets the OS page model weights.
TTFT           Time to first token.
Protocol card  Static, expert-reviewed emergency instructions shown without AI.
Pack           Signed, versioned SQLite bundle of guides, chunks and vectors.
Red-flag       A query indicating immediate danger to life.
